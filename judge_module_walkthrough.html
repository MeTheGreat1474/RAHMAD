Judge module walkthrough — each section of judge.py explained

Config API constants URL · model · limits

These three lines wire the module to OpenRouter. _MAX_TEXT_CHARS caps how much article text is sent so you don't blow the model's context window.

What to adjust
Only touch _MODEL_ID if you want to swap models. _MAX_TEXT_CHARS = 6000 is safe for most articles — raise it if your articles are very long and the model supports it.
_OPENROUTER_URL = "https://openrouter.ai/api/v1/chat/completions"
_MODEL_ID       = "openrouter/owl-alpha"
_MAX_TEXT_CHARS = 6000
Adjustable System prompt Role · task · output schema

This is the most important thing to tune. It tells the model who it is, what it receives, and how to reason. The last paragraph enforces strict JSON output — keep that part intact.

Good things to tweak
The reasoning instructions — "Reason carefully through the article's claims, writing style, internal consistency, emotional framing, and any factual red flags." You can add more heuristics here, e.g. add "Look for sensationalist headlines mismatched with body content" or "Check if named sources are verifiable."
Do NOT change
The JSON schema block at the bottom. The parser in _parse_response() depends on these exact field names.
_SYSTEM_PROMPT = """\
You are a professional news fact-checker ...

Reason carefully through the article's claims,
writing style, internal consistency, emotional
framing, and any factual red flags. The EP signal
is one useful data point — you may agree or
disagree with it based on your own analysis.

IMPORTANT: Respond with a single valid JSON only.
{
  "verdict": "REAL CONTENT"|"MANIPULATED CONTENT"|"INCONCLUSIVE",
  "color_class": "real"|"manipulated"|"inconclusive",
  "confidence": "<number>%",
  "justification": "<2–3 sentence explanation>",
  "key_facts": ["<obs 1>", "<obs 2>", "<obs 3>"]
}"""
Adjustable User message template How EP signal + article are formatted

This is the actual message sent per-request. It stitches the EP result (label, probability, confidence) with the cleaned article text. The note after the EP block tells the model not to blindly trust it.

What to tweak
The framing note — "treat it as evidence, not as a definitive answer." You can strengthen or weaken how much authority the EP carries, e.g. change it to "The EP signal is highly reliable for clear-cut cases." You can also add extra context fields here (e.g. article source URL, publish date) if your frontend sends them.
_USER_TEMPLATE = """\
=== EARLY PREDICTOR SIGNAL ===
Label       : {ep_label}
Probability : {ep_prob:.4f}  (0.0 = Real, 1.0 = Fake)
Confidence  : {ep_confidence}

Note: treat it as evidence, not a definitive answer.

=== ARTICLE TEXT ===
{llm_text}

Analyse the article and return your verdict as JSON."""
Config Judge.__init__ temperature · max_tokens · API key

Sets up the model parameters. temperature=0.2 keeps outputs deterministic and consistent — good for structured JSON. The API key is read from your .env file automatically.

What to tweak
temperature: raise toward 0.5–0.7 if you want more varied justifications. Keep it low (0.1–0.3) for consistent JSON structure. max_tokens=1024 is plenty — lower it to 512 to cut cost if justifications are being truncated anyway.
def __init__(self, api_key=None, temperature=0.2, max_tokens=1024):
    self.api_key     = api_key or os.environ.get("OPENROUTER_API_KEY")
    self.temperature = temperature
    self.max_tokens  = max_tokens
Fixed _call_api HTTP request to OpenRouter

Sends the POST request. The HTTP-Referer and X-Title headers are required by OpenRouter for rate-limit attribution — they don't affect the response. timeout=60 prevents the Flask thread from hanging if OpenRouter is slow.

What to tweak
Only timeout if needed. You can also add "stream": True here later if you want to stream the response to the frontend.
headers = {
    "Authorization": f"Bearer {self.api_key}",
    "HTTP-Referer":  "https://rahmad.local",
    "X-Title":       "RAHMAD Fake News Detector",
}
payload = {
    "model": _MODEL_ID,
    "messages": [system_msg, user_msg],
    "temperature": self.temperature,
    "max_tokens":  self.max_tokens,
}
Logic _parse_response JSON extraction + verdict normalisation

Strips markdown fences if the model wraps its output in them, parses JSON, then normalises the verdict string to one of three exact values. This is what maps "FAKE", "MANIPULATED", "FALSE" etc. to "MANIPULATED CONTENT".

What to tweak
The normalisation rules. Currently: if "REAL" in verdict → "REAL CONTENT", if "MANIPULATED" or "FAKE" → "MANIPULATED CONTENT", else "INCONCLUSIVE". Add more aliases here if the model keeps returning unusual strings like "MISINFORMATION" or "SATIRE".
if "REAL" in raw_verdict and "MANIPULATED" not in raw_verdict:
    verdict, color_class = "REAL CONTENT", "real"
elif "MANIPULATED" in raw_verdict or "FAKE" in raw_verdict:
    verdict, color_class = "MANIPULATED CONTENT", "manipulated"
else:
    verdict, color_class = "INCONCLUSIVE", "inconclusive"
Fallback _fallback_response Safe output on any error

If the API call fails (bad key, network timeout, rate limit) or the JSON can't be parsed, this returns INCONCLUSIVE with 0% confidence rather than crashing Flask. The error message is passed through to the frontend.

What to tweak
The fallback justification text shown to users. Currently it exposes the technical error — you may want to replace it with a friendlier message for production.
return {
    "verdict":       "INCONCLUSIVE",
    "color_class":   "inconclusive",
    "confidence":    "0.0%",
    "justification": f"Judge Module error: {error_msg}",
    "key_facts":     ["Check OPENROUTER_API_KEY and connection."],
    "links": [],
}
